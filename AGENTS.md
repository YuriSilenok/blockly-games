# Правила работы над проектом

- Долгие realtime-поединки с возрождениями не ограничивать суммарными 90 CPU-секундами процесса: обновлять 90-секундный бюджет после продвижения симуляции (каждые 50 шагов), сохраняя лимиты памяти и 4 секунды на вызов QuickJS. Для обучения/песочницы прежний общий CPU-лимит сохраняется. При аварии записывать matches.failure и в журнал job/match/returncode/game_time, не выдавать остановленный бой за завершённый в прямом показе. Ошибочную серию king можно продолжить только явным подтверждением в статистике через /api/admin/rounds/:id/resume; сервер проверяет роль/CSRF, error-статусы раунда и задания и незавершённый турнир. Сохраняются job, series_state и завершённые поединки; только прерванный поединок запускается заново. Самостоятельно не перезапускать пользовательский бой во время диагностики.

- Новые раунды имеют настройки mode (survival/king), respawns (0–1000) и kill_target (0–1000). При нуле возрождений и выключенном счёте обычное выживание; лимит потоплений разрешён только с возрождениями либо в «Царе горы». В общем бою 2–4 команды, в серии «Царь горы» 2–64 команды, одновременно всегда две. Очередь сохранять в round_players.queue_order, стрелки в подготовке меняют порядок списка, повтор состава копирует настройки и очередь. Создание/сохранение по-прежнему не запускает бой.
- Возрождение серверной утки: случайная свободная точка внутри 10–90, 100 ХП, сброс движения и новый Interpreter исходного алгоритма, уменьшение respawnsLeft; ошибки алгоритма не зацикливать возрождениями. Потопления соперников сохраняются между жизнями, самопотопления не считаются. Порог счёта останавливает бой сразу; если утки закончились раньше порога, победителя по выживанию не назначать. На старте отвергать математически недостижимый лимит потоплений. В записях сохранять generation/остаток возрождений; PondRenderer не интерполирует телепортацию между поколениями. При X=0 обучение и песочница сохраняют обычное поведение.
- «Царь горы» проводится через server/king.py одним исполнителем: победитель 1 на 1 получает 1 очко (потопление/победу), полный ХП и новый запуск алгоритма против следующего; проигравший в конец очереди. При минуте без урона побеждает большее ХП; при равенстве ниже 100 обе утки уходят в конец без очков. При 100:100 обе получают личный счётчик таких исходов подряд, при втором — дисквалификация; любой другой итог личного боя сбрасывает этот счётчик. Остановка при достижении kill_target, одной оставшейся команде или дисквалификации всех. Возрождения внутри каждого поединка задаются respawns; между поединками обе начинают заново с полным ХП. Сохранять очередь/счёт/предупреждения после каждого поединка в series_state атомарно с round_bouts. Завершённые поединки при восстановлении не пересчитывать; все записи доступны в статистике через общий проигрыватель. Миграция tournament-modes-v1 предварительно сохраняет резервную копию базы.

- Раунд запускается только кнопкой «Запустить игру» у пруда, после сохранения состава (кнопка «Сохранить состав» не запускает бой). До запуска виден общий список скорости 0,1×/0,25×/0,5×/1×/2× без подписи; значение хранится локально для администратора и переносится на следующие бои. Скорость фиксируется сервером в rounds.playback_speed при start, проверяется по разрешённым значениям, управляет только реальным темпом выдачи кадров, а не физикой/игровым временем. В прямом показе время и буфер масштабируются по скорости конкретного раунда, список заблокирован до окончания текущего боя. В записях скорость по-прежнему меняется локально без запуска движка. Смена турнира сбрасывает выбор подготовленного раунда и отключает запуск до загрузки нового состава.

- Прямой показ турнира получает через /api/admin/live порции последовательных кадров из ограниченного кольцевого буфера исполнителя (150 кадров, 3 игровые секунды при 50 кадрах/с), с курсором match_id/after. PondBattlePlayer хранит ограниченную очередь и интерполирует соседние исходные кадры по игровому времени с задержкой около 0,5 с, вместо сглаживания каждого сетевого ответа за фиксированные 250 мс. При недостатке данных время замирает, доигрывать финальные кадры после завершения боя; неподвижный финал постоянно не рисовать. Загрузку/JSON live тоже выполнять в общем Web Worker с запасным обычным fetch. Во время прямого боя busy запрещает фоновую загрузку/пересоздание статистики и редакторов раундов; на отображение буфера и кадров это не влияет. Без повторной симуляции и без отдельной отрисовки.

- Панель подготовки раундов показывает только черновики, очередь и текущие бои; завершённые/ошибочные раунды и кнопки «Смотреть запись» в ней не дублировать. История раундов и просмотр записей находятся в статистике. Единственная кнопка повторения состава последнего раунда сохраняется.

- В разделе администратора «Обучение и допуск» список включает действующих администраторов с пометкой роли. Для обычных пользователей есть подтверждаемая кнопка «Назначить администратором»; API /api/admin/users/:id/promote проверяет текущую роль вызывающего, CSRF, логин целевого действующего пользователя и меняет только роль. Новый администратор получает полные права управления, без автоматического зачёта обучения; роль берётся из базы при каждом запросе. В гистограмме администраторов не учитывать, кнопки назначения/удаления для них не показывать. Понижение роли не добавлено.

- Создание раунда, в том числе «Новый раунд с этим составом», не запускает бой автоматически: сохранить черновик/состав, запуск отдельной кнопкой. После успешного создания переключать проигрыватель в прямой показ и плавно прокручивать к пруду тем же обработчиком, что кнопка «Прямой показ».

- Кнопка «Новый раунд с этим составом» одна на странице турнира и использует состав последнего по номеру раунда выбранного турнира, доступна только после его завершения/ошибки, до завершения турнира. Перед повтором обновлять последний раунд с сервера. В статистике группировать строки по раунду отдельным заголовком и сортировать участников по номеру выбытия по убыванию, одинаковые номера оставлять равными.
- Песочница и турнир используют общий интерфейс и контроллер PondBattlePlayer (portal/battle-player.js): готовая запись, пауза, перемотка, скорость, буферизация, Web Worker и общий PondRenderer. Турнирный прямой показ также проходит через этот компонент; при просмотре записи новые live-снимки не переключают режим самовольно, возврат кнопкой «Прямой показ». Новые раунды сохраняют replay v2 на каждом шаге; старые без кадров не пересчитывать, показывать недоступность повтора. Турнирные записи API /api/admin/matches/:id/replay доступны администратору, без исходного кода. Прямой показ и очередь фильтруются выбранным турниром.

- В разделе администратора «Обучение и допуск» есть удаление пользователя с подтверждением точным логином. Проверять роль и CSRF сервером; администраторов удалять нельзя. Удаление логическое (users.deleted): запретить вход/сеансы/приглашения и операции с командой, убрать из активного списка и гистограммы, удалить прогресс и проверочные числа. Алгоритмы, отправки, записи и результаты сохраняются, логин остаётся занят для истории. Участник выходит из команды; при удалении капитана команда распускается с отменой приглашений. Пока есть его queued/running задания или queued/running раунд команды, удаление запрещено. Отметку прохождения удалённому пользователю выдавать нельзя.

- Админка разделена на обзор /admin (portal/admin.html), турниры (admin-tournaments.html, admin.js), алгоритмы (admin-algorithms.html/js) и обучение с допуском (admin-training.html/js). Общая навигация и проверка роли интерфейса — admin-shell.js, API по-прежнему проверяет роль сервером. На странице турниров только управление турниром/приёмом, свёрнутое создание нового, подготовка раундов, общий PondRenderer прямого показа и отдельная статистика. Не загружать библиотеку/обучение и не запускать опрос боёв на других страницах админки. Просмотр блоков возвращает к библиотеке алгоритмов. Выбранный турнир сохранять в пределах сессии, новый после создания выбирать автоматически.

- После уровня 9 вставлена копия — новый уровень 10: те же блоки и ограничения (не более двух активных циклов, победа тараном), у целей по порядку 10, 20 и 40 ХП. Новых блоков в справке нет. Прежние уровни 10–19 и их прогресс/работы сдвинуты на 11–20, всего 20 уровней; версия черновиков v7, новый уровень пустой. Все прежние номера >=10 ниже относятся к состоянию до вставки. Полная панель теперь с 17, перенос успешной программы с перехода 17→18, финал — 20. Из query пересчитывать nm после фактического mm, чтобы готовая сборка не ограничивала вход последним старым уровнем.
- На первом уровне категория «Пруд» мигает до первого клика; факт клика хранится локально отдельно для пользователя. Создание команды доступно только после полного обучения, проверять в транзакции сервера и скрывать форму до допуска. В админке гистограмма показывает количество участников с каждым числом пройденных уровней (0–20), без администраторов; есть поиск пользователей и подтверждаемая отметка о полном прохождении. Отметка заполняет только недостающий прогресс пустыми решениями, существующие решения сохраняет; все обычные проверки доступа используют этот прогресс.

- Администратор может переименовывать стратегии любых авторов, включая отправленные и архивные, через раздел «Все алгоритмы». Проверять роль и CSRF сервером, название 1–80 символов, отсутствие другого алгоритма с тем же названием у автора (включая архив). Менять только название и дату изменения библиотеки, название в таблице песочницы и заявках незавершённых турниров; код/XML, имена в записях боёв и снимках раундов сохранять. Переименование не снимает запрет перезаписи отправленного алгоритма. При завершении ранжирования брать актуальные названия из библиотеки, чтобы параллельное переименование не терялось.

- После первой отправки в песочницу или турнир запретить перезапись алгоритма под тем же названием у автора, включая архивные записи и неудачные отправки. Загружать и дорабатывать можно, сохранять доработку — под другим названием. До отправки перезапись разрешена. Каждое новое название — отдельный неизменяемый алгоритм со своим местом; прежнее правило выбора лучшей версии отменено. В песочницу тот же алгоритм отправляется один раз. Повторная турнирная заявка меняет только флажки, но не код/XML снимка. Проверять запрет в транзакции сохранения, сериализуя с отправками. Этот пункт заменяет прежние правила перезаписи опубликованного алгоритма и выбора лучшей версии ниже.

- В админке раздел «Все алгоритмы» показывает библиотеку всех авторов, включая архивные записи, с поиском по названию и логину и просмотром в виде блоков готового редактора без редактирования. Режим admin_algorithm не требует завершения обучения от администратора, не запускает бой и не сохраняет черновики; код и XML в интерфейсе не показывать. Список и содержимое доступны только через серверную проверку роли администратора; участникам исходный код не раскрывать.

- Не запускать тесты без отдельной просьбы пользователя.
- Цикл воспроизведения записи работает синхронно через requestAnimationFrame, без await запросов и разбора JSON в кадре. Подгружать два следующих фрагмента заранее, держать ограниченный кэш; загрузку и разбор выполнять в replay-loader.js (Web Worker с запасным вариантом для неподдерживаемого браузера). При недостатке данных приостанавливать игровое время с индикатором загрузки, без скачка вперёд. На паузе не рисовать неизменный кадр постоянно. Во время просмотра не пересоздавать таблицы и список боёв; ХП обновлять только при изменении текста, ползунок и время — с ограниченной частотой. Общий PondRenderer кэширует объединение событий соседних кадров и текстуры радара, с ограничением памяти.
- Обучение, редактор, прямой показ турнира и записи песочницы используют общий PondRenderer (pond/renderer.js): спрайты, следы движения, радар, траектории и эффекты попаданий из учебного Пруда. Адаптеры готовых сборок сохраняют их звуки и обновление ХП. Не создавать отдельные реализации отрисовки для турнира и песочницы; общий interpolate используется для записей и плавного прямого показа. Повтор не запускает движок.
- Самостоятельный редактор доступен по /editor только после всех 19 уровней, без обязательной команды. Пункт «Редактор алгоритмов» в меню скрыт до завершения обучения; проверять доступ и сервером. Из редактора отправлять сохранённый алгоритм в песочницу (любой выпускник) или на турнир (капитан, алгоритмы своей команды). Страница песочницы показывает места и записи, отправка вынесена в редактор. Старые ссылки pond-duck.html сохраняются; параметры ссылки /editor не терять при перенаправлении.
- Оба каталога nginx /var/lib/nginx/proxy и /var/lib/nginx/body должны принадлежать www-data:www-data с правами 0700. Неверные права body приводят к HTML-ошибке nginx при сохранении более объёмных стратегий; это не ограничение количества алгоритмов. Поддерживать права в автообновлении. На не-JSON ответ API показывать понятную русскую ошибку сервера/сети, а не сообщение о расположении сервиса учётных записей.
- Формат записи песочницы v2 сохраняет каждый шаг движка (50 кадров/с), события сканирования с углом, шириной сектора, позицией и временем, а также начало/конец и время полёта снарядов. Проигрыватель рисует секторы радара и плавный полёт по записанной траектории с дугой, тенью и вспышкой попадания, без запуска алгоритмов. Старые записи сохраняются и получают пояснение об отсутствии событий радара/полёта; не пытаться восстановить их новой симуляцией.
- Песочница независима от турниров, команд и капитанства. Любой завершивший обучение пользователь отправляет свой сохранённый алгоритм; каждому алгоритму принадлежит отдельное место. При повторной отправке сохранять версию с лучшим местом (при равенстве — прежнюю). Место искать бинарным поиском, встречи 1 на 1 до двух побед, максимум три боя; при равном здоровье выигрывает более ранняя отправка. Старт — два разных случайно выбранных угла с отступом 10. До начала таблицы проверочный соперник вне рейтинга обеспечивает проверку и запись боя.
- Серверные бои обучения, турнира и песочницы проходят через одного исполнителя, без одновременных боёв. В песочнице собственные таблицы и снимки отправок; не менять турнирные заявки и результаты. Сохранять кадры проведённых боёв сжатыми порциями; повтор читает запись и поддерживает паузу, перемотку и замедление, без запуска симуляции. Записи доступны участникам соответствующего боя и администратору, исходный код алгоритмов не отдавать с записью.
- Отправленные в песочницу алгоритмы и их историю сохранять при удалении дубликатов библиотеки: архивировать исходные записи, на которые ссылаются sandbox_submissions. Редактор в режиме ?sandbox=1 доступен выпускнику без команды.
- В турнире и тренировочном пруду стартовые позиции только (10,10), (90,10), (90,90), (10,90). Перед боем случайно распределять эти углы между утками, без повторов. В административном раунде от двух до четырёх команд; старые черновики с большим составом не запускать до изменения состава. Прежнее ограничение до 25 команд заменено четырьмя углами.
- На уровне 6 допускается не более одного активного цикла любого типа. Проверять в браузере и на сервере; отключённые циклы не учитывать. Сохраняются обязательные цикл и измерение скорости, максимум два блока «Плыть» и победа тараном. Условия и вложенность не фиксировать.
- В production версию записывает root-шаг ExecStartPre через deploy/write-version.sh в /var/lib/pond/deployed-revision (0644); приложение читает файл без доступа к Git. При откате тот же шаг записывает хеш восстановленного коммита. Не полагаться только на git -c safe.directory из-под pond: установленный Git на VPS отвергает репозиторий с другим владельцем.
