# Пруд: обучение и турнир команд

Новые раунды «Царь горы на вылет» используют очередь: победитель поединка проходит в следующий круг, проигравший остаётся против очередного соперника. Последний проигравший в круге выбывает; прошедшие команды образуют перемешанную очередь следующего круга. Раунд идёт до последней команды, лимит побед не применяется. Правила равных ХП, возрождений и дисквалификации за два личных исхода 100:100 сохраняются. Уже начатые и завершённые раунды старого king сохраняют прежнюю механику; новые черновики и повтор состава используют king_elimination. Раскрытый список поединков и выбранная запись не сбрасываются фоновыми обновлениями статистики.

Каждый раунд имеет собственную таблицу статистики. В «Царе горы» столбцы: «Команда», «Алгоритм», «Утонул», «Здоровье», «Потоплений». «Утонул» считает все потопления своей утки за раунд; «Здоровье» суммирует остатки ХП при каждой победе перед перезапуском обеих уток и при итоговой победе по ХП; «Потоплений» считает реально потопленных соперников, включая жизни до возрождения. Это отдельные показатели от числа победных поединков серии. Новые записи содержат точные накопительные значения; старые итоги используются без симуляции, недостающая сумма ХП до возрождений отображается как «—» с пояснением. В общем бою сохраняются столбец «Выбыл» и конечный остаток ХП.

В «Царе горы» при дополнительном возрождении поединок начинается заново для обеих уток: по 100 ХП, новые стартовые углы, сброс снарядов и движения, алгоритмы запускаются сначала. Возрождение списывается только у потопленной утки. Счёт серии сохраняется; перезапуск выжившей утки не считается расходом её жизни. Общий бой по-прежнему использует индивидуальное возрождение.

«Остановить раунд» у пруда требует подтверждения: ожидающий раунд снимается с очереди, активный бой и дальнейшая серия останавливаются с сохранением проведённых поединков и частичной записи. Победитель не назначается. После статуса «Остановлен» можно создать новый раунд с тем же составом. «Удалить раунд» доступно для черновиков в подготовке, для финальных раундов — в заголовке статистики. Удаление скрывает раунд и его записи, сохраняя архив БД; активный раунд сначала нужно остановить и дождаться освобождения исполнителя. Алгоритмы и номера остальных раундов сохраняются.

Полные пользовательские правила опубликованы на странице `portal/tournament-rules.html` («Правила турниров»), доступной из турниров и админки. Они описывают участие и команды, заявки, возрождения, условия победы, «Царь горы», ничьи, дисквалификацию, статистику и записи.

Если серия «Царь горы» оборвалась из-за серверной ошибки, в статистике доступна кнопка «Продолжить прерванную серию» с подтверждением. Уже проведённые поединки и счёт сохраняются; заново начинается только прерванный поединок. Прямой показ явно сообщает об аварии. Для долгих боёв с возрождениями CPU-бюджет исполнителя обновляется по мере продвижения симуляции; ограничения памяти и времени одного вызова QuickJS сохраняются.

При создании раунда можно выбрать общий бой или «Царь горы на вылет» и число возрождений. В общем бою доступен лимит потоплений при включённых возрождениях; в режиме на вылет счёт не определяет окончание раунда. При нуле возрождений и выключенном лимите общий бой остаётся обычным выживанием.

В общем бою участвуют 2–4 команды, в «Царе горы на вылет» — 2–64 команды. Новый режим сохраняет очередь и последовательные поединки один на один, исключая последнего проигравшего каждого круга. При минуте без урона побеждает большее ХП, равенство ниже 100 возвращает обоих в очередь, а два личных исхода 100:100 подряд приводят к дисквалификации. Счёт, круги, очередь и записи сохраняются между перезапусками.

Перед запуском раунда администратор сохраняет состав, выбирает скорость у пруда и нажимает «Запустить игру». Создание раунда и сохранение состава бой не запускают. Скорость переносится на следующие бои и сохраняется при обновлении страницы. При старте сервер фиксирует выбранный темп прямого показа; физика и игровые секунды не меняются. Во время текущего боя скорость заблокирована, а при просмотре записи её можно менять свободно.

Прямой показ турнира использует последовательные исходные кадры из ограниченного серверного буфера, курсор загрузки и общую интерполяцию PondRenderer. Проигрыватель отстаёт примерно на 0,5 секунды для сглаживания неравномерной доставки, при недостатке кадров ждёт подгрузки без скачка времени. Загрузка и разбор JSON выполняются в Web Worker; фоновое обновление статистики во время показа приостановлено. Завершившийся бой доигрывается до последнего кадра, затем постоянная перерисовка прекращается.

Тестовые стратегии используют шаг поиска 1–2°, удерживают обнаруженную цель, повторяют выстрелы и сближаются за пределами дальности пушки. Для явно разрешённой администратором замены тестовых снимков через БД есть инструмент `python -m server.update_test_strategies --tournament test --apply`: резервная копия, одна транзакция, только основные стратегии `test01`–`test11`, согласованные код/XML библиотеки и заявки. Имена и история раундов не меняются. При ожидающих/активных раундах, завершённом турнире, неоднозначных заявках или наличии отправок этих алгоритмов в песочнице операция отменяется. Обычная пользовательская перезапись отправленных алгоритмов остаётся запрещённой.

Для явного создания тестовых участников доступен административный инструмент `python -m server.seed_test_tournament --tournament test --credentials /root/pond-test-accounts.csv --apply` (с серверным `POND_DATA_DIR`). Он делает резервную копию базы, одной транзакцией создаёт `test01`–`test11`, засчитывает обучение, создаёт личные команды и разные стратегии с согласованными блоками/XML, заявляет их основными в открытый турнир. Бои не запускает. При существующем логине/команде или неоднозначном/закрытом турнире изменения отменяются; повторный запуск не перезаписывает пользователей и стратегии. Файл паролей создаётся с правами 0600 и не должен попадать в Git; локальную копию хранить в исключённом каталоге `var/`.

Назначение других администраторов доступно в разделе «Обучение и допуск»: найди пользователя по логину и нажми «Назначить администратором», затем подтверди выдачу полных прав. Новый администратор получает доступ после обновления страницы. Прогресс обучения при назначении не меняется. Действующие администраторы отмечены в списке и не входят в гистограмму участников.

Турнир и песочница используют общий проигрыватель `portal/battle-player.js`: пауза, перемотка, изменение скорости, буферизация и отрисовка через PondRenderer. Новые турнирные раунды сохраняют полную запись боя; администратор открывает её кнопкой «Смотреть запись» в списке или статистике раундов. «Прямой показ» возвращает к текущему бою выбранного турнира. Старые бои без записи повторно не симулируются. В статистике отдельная группа на раунд, участники идут по убыванию номера выбытия. Единственная кнопка «Новый раунд с этим составом» повторяет состав последнего раунда после его завершения.

В разделе администратора «Обучение и допуск» кнопка «Удалить пользователя» требует ввода точного логина. Удаление закрывает учётную запись и все сеансы, убирает её из активных списков и удаляет прогресс обучения. Алгоритмы и история соревнований сохраняются, логин повторно не используется. При удалении капитана команда распускается; активные проверки и раунды нужно сначала завершить. Учётные записи администраторов удалить нельзя.

Админка `/admin` — обзор с отдельными разделами «Турниры», «Алгоритмы» и «Обучение и допуск». Управление турниром, раунды, прямой показ и статистика находятся на отдельной странице `portal/admin-tournaments.html`; библиотека и обучение на ней не загружаются. Выбранный турнир запоминается на время сессии, новый турнир после создания выбирается автоматически. Между разделами доступна общая навигация; смена пароля остаётся в личном кабинете.

В курсе 20 уровней. После девятого добавлена копия с разным здоровьем целей: 10, 20 и 40 ХП; блоки и ограничения такие же, новых блоков в справке нет. Прежние уровни 10–19, прогресс и черновики перенесены на 11–20. Новый десятый начинается пустым и непройденным. На первом уровне категория «Пруд» мигает до первого клика пользователя.

Команду можно создать только после завершения обучения. В админке раздел «Прогресс обучения» показывает гистограмму числа пройденных уровней у участников и позволяет найти пользователя по логину и отметить его обучение пройденным с подтверждением. Существующие решения при этом сохраняются, недостающие уровни засчитываются без решения; открываются редактор, песочница и турниры.

Готовые сборки Pond Tutor и Pond Duck сохранены без компиляции. Интерфейс и документация доступны на русском языке. Рабочий сайт: https://силенок.рф.

«Редактор алгоритмов» — отдельный пункт меню, появляющийся после завершения всех 20 уровней. Адрес `/editor`; команда для работы не нужна. В редакторе можно сохранять и загружать алгоритмы, тренироваться, отправлять собственный алгоритм в песочницу, а капитану — алгоритмы участников команды на турнир. Страницы турнира и песочницы показывают результаты и ведут к редактору.

За отображение пруда во всех режимах отвечает один компонент `pond/renderer.js`: обучение, редактор, прямой показ турнира и повторы используют одинаковые спрайты, радар, следы движения, дугу полёта снарядов и эффекты попаданий. Отрисовка повторов использует сохранённые кадры и события, без повторного исполнения алгоритмов.

Песочница (`/sandbox`) — отдельная от турниров таблица алгоритмов. Любой выпускник может отправить свой сохранённый алгоритм один раз, без команды. Каждому алгоритму принадлежит своё место. Сервер бинарным поиском подбирает соперников и проводит встречи один на один до двух побед (не более трёх боёв). Выбора лучшей версии больше нет: доработка сохраняется под другим названием и получает отдельное место. При равном здоровье побеждает более ранняя отправка. Утки стартуют в разных случайно распределённых углах с отступом 10. Бой заканчивается при одной оставшейся утке или после минуты без урона. Первый алгоритм встречается с проверочным соперником вне таблицы. Отправки в песочницу не изменяют результаты турниров.

Все серверные бои идут последовательно через общего исполнителя. Песочница показывает текущие места, очередь, историю отправок и бои своих алгоритмов, в том числе когда они были соперниками чужих отправок. Сервер сохраняет фактические кадры боёв сжатой записью в базе. Проигрыватель читает запись порциями, позволяет поставить паузу, перемотать и выбрать скорость 0,1×, 0,25×, 0,5×, 1× или 2×. Просмотр не запускает новую симуляцию и не зависит от последующих изменений алгоритма. Записи доступны участникам боя и администратору; код противника в запись не включён. Вход в редактор из песочницы (`pond-duck.html?sandbox=1`) доступен без команды.

Новые записи формата v2 включают все шаги движка (50 кадров/с), направления и секторы сканирования, позиции и время запуска/попадания снарядов. При просмотре видны лучи радара и плавный полёт снарядов по дуге с тенью и вспышкой попадания. В старых записях этих событий нет: они остаются доступными с соответствующим пояснением, без повторной симуляции боя.

Проигрыватель заранее загружает следующие фрагменты и разбирает их в отдельном потоке браузера. Цикл отрисовки не ждёт сеть; при нехватке данных появляется индикатор, а время записи останавливается до загрузки. Кэш ограничен восемью фрагментами. Во время воспроизведения фоновое обновление таблиц приостановлено и возобновляется на паузе; неподвижный кадр постоянно не перерисовывается.

Обучение состоит из 20 экспериментов. Справка показывает новые блоки в исходном SVG, кратко описывает назначение, входные параметры и возвращаемое значение, затем показывает задание. Если новых блоков нет, остаётся только задание. Начиная с перехода 17 → 18 успешное решение переносится на следующий уровень, в том числе между устройствами; собственная сохранённая работа уровня при открытии имеет приоритет. После серверного подтверждения уровня 20 пользователь автоматически переходит к турнирам. До окончания обучения страницы и API турниров закрыты для участников.

Завершение курса не закрывает обучение: в личном кабинете остаётся кнопка возврата к уровням, а переход к турнирам вынесен отдельно. При повторной победе на уровне 20 автоматического перехода нет. На уровне 6 допускается не более двух активных блоков «Плыть», на уровне 8 — не более одного; ограничения проверяются в браузере и на сервере, отключённые блоки не учитываются.

Уровень 13 — таран по всем направлениям. Уровень 14 — копия 12 с блоками «Плыть» и «Стоп». У игрока 1 ХП, у трёх целей по 100 ХП. Игрок находится в (10, 10), цели — в (90, 10), (90, 90), (10, 90): со старта по ним нельзя попасть даже с учётом радиуса взрыва. Сохраняются требования радара, стрельбы, ровно одного цикла и одного «Если». При перестановке уровней их прогресс и черновики перенесены вместе с заданиями.

Вход в личную учётную запись обязателен перед обучением. Ученик выбирает логин и пароль при регистрации. На странице турниров капитан создаёт команду и приглашает до двух зарегистрированных игроков по логинам. Приглашение принимается или отклоняется в личном кабинете; один игрок может состоять только в одной команде. Капитан может отозвать приглашение, исключить участника или распустить команду. Роспуск сохраняет личные алгоритмы и историю турниров; во время запущенного раунда нужно дождаться его завершения. Прогресс обучения хранится в SQLite; сервер подтверждает прохождение повторным исполнением решения.

В редакторе участник сохраняет именованные версии алгоритмов в личной библиотеке, загружает их и выбирает от 1 до 3 тренировочных противников. Любой утке можно назначить свой сохранённый алгоритм, доступный для тренировок чужой алгоритм или оставить её без алгоритма; для своей утки также доступны текущие блоки редактора. Личные версии не изменяются при публикации: заявка хранит отдельный снимок. На турнир можно заявить несколько версий от команды, но основной только один. Отдельные флажки управляют основным алгоритмом и разрешением тренировки для других команд. Приём новых заявок можно закрыть; выбор основного алгоритма остаётся доступен до завершения турнира.

Отправлять заявки может только капитан: ему доступны сохранённые алгоритмы всех текущих участников команды с указанием автора. Владельцем остаётся автор. До отправки повторное сохранение под тем же названием перезаписывает алгоритм. После первой отправки в песочницу или турнир перезапись запрещена, в том числе для архивного алгоритма или неудачной отправки. Его можно загрузить, доработать и сохранить под другим названием. При загрузке поле названия заполняется автоматически. Повторная турнирная заявка меняет только флажки основного алгоритма и доступности для тренировки, сохраняя опубликованный снимок и прошедшие раунды.

Администратор создаёт турнир, вручную создаёт раунд, выбирает команды с основными алгоритмами и запускает общий бой. От двух до четырёх команд одновременно; стартовые позиции — углы (10, 10), (90, 10), (90, 90), (10, 90). Перед каждым боем углы случайно распределяются без повторов. Та же расстановка используется в тренировочном пруду. Раунд завершается при одной оставшейся утке или после 60 игровых секунд без уменьшения здоровья любой утки. «Выбыл» — порядковый номер выбытия; оставшиеся утки получают одинаковый следующий номер. «Здоровье» — остаток ХП в конце боя, «Потоплений» — число противников, потопленных прямым уроном снаряда или столкновения (самопотопления не учитываются). Состав и алгоритмы фиксируются при запуске. Каждый раунд имеет отдельный отчёт; все раунды доступны в общей таблице. Из отчёта можно немедленно запустить новый раунд с тем же составом и текущими основными алгоритмами. Завершение турнира запрещено, пока есть незавершённые запущенные раунды.

С уровня 16 открыта полная панель Пруда: команды утки, логика, циклы, математика, случайные числа, переменные и функции. Панель совпадает с турнирным редактором. На уровне 15 беглецы обходят квадрат против часовой стрелки; границы маршрута — координаты 10 и 90. Приём алгоритмов администратор может многократно останавливать и возобновлять; это не завершает турнир. Окончательное завершение — отдельное действие.

Миграция `algorithm-library-v1` переносит прежние лучшие алгоритмы из таблицы в личные библиотеки авторов и заявки команд; исходная история не удаляется. Перед миграцией создаётся резервная копия базы в каталоге `backups`. Автоматический бинарный поиск места больше не запускается: соревнование проводится вручную по раундам.

В личном кабинете участник и администратор могут менять собственный пароль с подтверждением текущего. Сессии на других устройствах при этом завершаются. Капитан управляет названием и составом команды; участник может выйти из команды. Старые личные команды и результаты автоматически переносятся в новую схему без потери прогресса.

Панель `/admin` позволяет создавать и открывать/закрывать турниры, наблюдать текущий бой в реальном времени и просматривать таблицы. Исходный код ученику не отображается: работа ведётся с блоками.

## Запуск

Python 3.8, зависимости: `server/requirements.txt`. Из корня репозитория:

```sh
python -m venv .venv
.venv/bin/pip install -r server/requirements.txt
.venv/bin/python -m server.app
```

Приложение слушает `127.0.0.1:8000`. Настройки окружения и инструкция для VPS, HTTPS, резервного копирования и автообновления: [deploy/README.md](deploy/README.md).

Публикация в GitHub Pages отключена, workflow удалён. Основной сайт на VPS автоматически обновляется из ветки `master` с помощью systemd-таймера.

Клиентские изменения находятся в `appengine/pond/course.js`, `course-data.js`, `tournament-editor.js` и `appengine/portal`. Интеграция подключается к сохранённым `generated/compressed.js`; сборочная цепочка не используется. Серверные файлы `server/runtime/avatar.js` и `battle.js` исполняются напрямую в QuickJS и сохраняют исходную физику Pond.

Тесты запускаются только по отдельной просьбе владельца.

Исходный проект: https://github.com/google/blockly-games. Лицензия Apache-2.0: [LICENSE](LICENSE).

На уровне 7 два цикла «пока» служат для ожидания снижения скорости между участками маршрута; проверяются только количество и тип циклов. Вложенность вводится на уровне 8: внешний цикл «повторить», внутри — «пока». Старые результаты и задания начиная с прежнего седьмого уровня сдвигаются на один; новый седьмой нужно пройти отдельно. Сохранённые работы восстанавливаются только для соответствующего задания. Подписи блоков переведены на русский, а «повторить» находится в группе «Циклы».

Уровень 9 — копия сцены уровня 8 с ограничением не более двух активных циклов, без проверки их типов и вложенности. Нужна победа тараном, стрельба запрещена. У каждой цели 10 ХП. Бывшие уровни 9–16 и их результаты перенесены на 10–17. Для нового девятого уровня поле изначально пустое, прошлые решения не переносятся.

Уровень 11 копирует сцену десятого и добавляет в «Циклы» блок «повторить X раз — выполнить». Программа должна использовать измерения обеих координат и содержать не более двух активных циклов. Прежние уровни 11–17 перенесены на 12–18 с сохранением прогресса; новый 11 нужно пройти отдельно.
