# Сервер Пруда

Приложение рассчитано на Python 3.8. Сервер использует стандартную библиотеку Python, SQLite и QuickJS. Готовые клиентские сборки не компилируются. Файлы `server/runtime` — исполняемый движок с исходной физикой Pond для серверных сражений.

Рабочий сайт: https://силенок.рф. VPS: 193.124.115.164.

## Установка на Ubuntu

Пакеты: `nginx`, `git`, `python3-venv`, `certbot`, `python3-certbot-nginx`.

Репозиторий размещается в `/opt/pond`, окружение Python — `/opt/pond-venv`. Установить зависимости: `/opt/pond-venv/bin/pip install -r /opt/pond/server/requirements.txt`.

Системный пользователь `pond` запускает приложение без доступа к домашним каталогам. `/var/lib/pond` принадлежит этому пользователю с правами 700. База SQLite, учётные записи, сессии, решения и таблицы хранятся здесь и не затрагиваются обновлением сайта.

Файл `/etc/pond.env` (root:root, 600):

```ini
POND_HOST=127.0.0.1
POND_PORT=8000
POND_DATA_DIR=/var/lib/pond
POND_ORIGIN=https://xn--e1afhclgq.xn--p1ai
POND_TRUST_PROXY=1
POND_ADMIN_PASSWORD_HASH=<PBKDF2-хеш начального пароля>
```

Скопировать `pond.service`, `pond-update.service`, `pond-update.timer` в `/etc/systemd/system/`. Выполнить `systemctl daemon-reload` и `systemctl enable --now pond pond-update.timer`.

Конфигурация nginx находится в `nginx.conf`. После установки сертификата Certbot дополняет её HTTPS и перенаправлением с HTTP. Сертификат продлевается стандартным `certbot.timer`.

## Автообновление

Таймер `pond-update.timer` раз в минуту проверяет `origin/master`. `update.sh` принимает только последовательные изменения Git, устанавливает зависимости и перезапускает сервис. При неудачной установке зависимостей или остановке сервиса после запуска возвращает предыдущий коммит. Таймер не запускает тесты и не компилирует клиент. GitHub-токен и SSH-пароль для обновлений не нужны: репозиторий публичный.

Перед запуском `pond.service` привилегированный `ExecStartPre` выполняет `write-version.sh`: записывает хеш текущего коммита в `/var/lib/pond/deployed-revision` с правами 0644. Приложение читает этот файл и выводит короткий хеш в подвале. При откате файл автоматически получает прежний хеш. Это не требует предоставлять пользователю `pond` права на Git-репозиторий.

На Ubuntu nginx работает от `www-data`; каталог буферов `/var/lib/nginx/proxy` должен принадлежать `www-data:www-data` с правами 0700. Автообновление поддерживает эти права. Если каталог принадлежит `nobody`, большие файлы могут загружаться не полностью (`ERR_CONTENT_LENGTH_MISMATCH`), а журнал nginx содержит `Permission denied` для этого каталога.

Те же владелец и права нужны каталогу тел запросов `/var/lib/nginx/body`; автообновление исправляет оба каталога. Ошибка прав `body` обрывает сохранение стратегий, когда запрос перестаёт помещаться в памяти nginx. Ограничения на количество сохранённых стратегий в приложении нет.

GitHub Pages отключён, workflow публикации удалён. Обновлением основного сайта управляет `pond-update.timer` на VPS.

Команды сопровождения:

```sh
systemctl status pond pond-update.timer
journalctl -u pond -u pond-update --since today
systemctl start pond-update.service
```

Автоматическое обновление активируется только после отправки коммита в `master`. Незакоммиченные локальные изменения на сервер не попадают. Настройки nginx и `/etc/pond.env` обновлением не перезаписываются.

## Администратор и резервная копия

Вход: `/account`, панель: `/admin`. Начальный логин — `silenok`; пароль соответствует указанному владельцем проекта. Пароль и его хеш в репозитории не хранятся. При первом запуске хеш берётся из закрытого `/etc/pond.env`; затем используется запись в базе. Для изменения пароля выполнить из `/opt/pond`: `sudo -u pond POND_DATA_DIR=/var/lib/pond /opt/pond-venv/bin/python -m server.password`.

Резервная копия при работающем приложении: `sudo -u pond POND_DATA_DIR=/var/lib/pond /opt/pond-venv/bin/python -m server.backup /var/lib/pond/backup.sqlite3`. Копировать готовый файл в защищённое хранилище вне VDS. Для восстановления остановить `pond`, вернуть файл как `pond.sqlite3`, удалить старые файлы `pond.sqlite3-wal` и `pond.sqlite3-shm`, восстановить владельца `pond` и запустить сервис.

## Команды и обновление схемы

При первом запуске новой версии существующие личные команды переводятся в отдельные команды с их создателями-капитанами. Учётные записи, прогресс, отправленные решения и места сохраняются. Состав команды ограничен тремя участниками; повторные решения разных участников сравниваются с общим лучшим алгоритмом команды.

Перед обновлениями, меняющими схему базы, создать резервную копию командой выше. При откате на версию со старой схемой требуется восстановить соответствующую копию базы после остановки сервиса.

Личный кабинет содержит смену пароля для любой роли. Для администратора есть прямая ссылка из панели управления. Начальный пароль из `/etc/pond.env` используется только при создании администратора: последующие изменения сохраняются в базе.

Перед первым переносом с 15 на 16 уроков приложение автоматически создаёт согласованную резервную копию `backups/before-split-level-seven.sqlite3` в каталоге данных. Перенос выполняется одной транзакцией и помечается в `course_migrations`: старый уровень 7 становится 8, следующие сдвигаются, новый 7 остаётся непройденным. Локальные черновики восстанавливаются с учётом прежних номеров, в новом уровне 7 перенос предыдущего решения не выполняется.

Перед добавлением копии восьмого уровня создаётся отдельная копия базы `backups/before-duplicate-level-eight.sqlite3`. Миграция `duplicate-level-eight` переносит прогресс и задания начиная с прежнего девятого уровня на один вперёд. Новый девятый уровень остаётся непройденным; прежние решения и черновики относятся к соответствующим перенумерованным заданиям.

Миграция `duplicate-level-ten` вставляет копию десятого уровня под номером 11 и сдвигает прежние уровни 11–17 на 12–18. Перед переносом автоматически создаётся `backups/before-duplicate-level-ten.sqlite3`. Проверки координат сохраняются, добавляется доступный блок повторения и лимит не более двух активных циклов. Черновики переносятся только к соответствующим заданиям; новый 11 стартует пустым.
